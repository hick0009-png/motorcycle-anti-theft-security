# งานแยก — ขยายความสามารถการติดตามตำแหน่งโหมดเฝ้ารถ

สถานะ: **ข้อเสนอ ยังไม่เริ่ม** · เจ้าของสั่งให้แยกออกจากแผนหลัก
วันที่บันทึก: 2026-09-01

---

## ทำไมต้องแยกก้อน

ของเดิมใช้งานได้ดีอยู่แล้ว สองข้อนี้เป็นการ **ขยายความสามารถ** ไม่ใช่การซ่อมของเสีย
ถ้าเอาไปปนกับแผน T1-T16 จะทำให้แยกไม่ออกว่าอาการที่เจอมาจากงานล็อก UI
หรือมาจากการแก้ตรรกะติดตามตำแหน่ง

**กติกาการแยก:**
- แตกสาขาจาก `feature/motorcycle-guard-protection` ต่างหาก ไม่ทำคาบเกี่ยวกับงาน T1-T16
- ไฟล์ที่แตะ: `LivePursuitCoordinator.kt` เป็นหลัก — **ไม่มีไฟล์ทับซ้อนกับแผนหลัก**
  (แผนหลักแตะ `SettingsScreen.kt`, `ProtectionUiModels.kt`, `ProtectionProfilePolicy.kt`,
  `PresentationTextCatalog.kt`, `AndroidProtectionRuntime.kt`, `IncidentEngine.kt`)
- ข้อยกเว้นเดียว: ถ้า T14/T16 ยังไม่เสร็จ **ห้ามแตะ `isPrimaryRole()` ในสาขานี้**
  เรื่องบทบาทเป็นของแผนหลัก งานนี้ไม่ยุ่ง

## สภาพปัจจุบัน (ยืนยันจากโค้ดแล้ว 2026-09-01)

```
Arm → ปักหมุดจุดจอด (ParkingAnchor)
    → เฝ้าระยะห่างจากหมุด
    → ห่างเกิน ~100 ม. + ยืนยัน 2 fix ห่างกัน 15-60 วิ + ความแม่นยำ ≤ 100 ม.
    → ข้อความ "กำลังถูกเคลื่อนย้าย" + เปิด Telegram live location 15 นาที
    → อัปเดตทุก ≥10 วิ หรือขยับ ≥10 ม.
    → หมดเวลา 15 นาที → หยุด
```

ค่าคงที่ที่เกี่ยวข้อง:
- `expiresAtMs = nowWall + 900_000L` — `LivePursuitCoordinator.kt:400`
- `pursuitAttempted = true` — กันไม่ให้เริ่มซ้ำในเซสชันอาร์มเดียวกัน `LivePursuitCoordinator.kt:396`
- `BASE_DISPLACEMENT_METERS = 100.0`, `REQUIRED_OUTSIDE_FIXES = 2`,
  `MIN/MAX_CONFIRMATION_SEPARATION_MS = 15_000/60_000` — `MovementDisplacementPolicy.kt:26-33`

**เกณฑ์ 100 ม. / 2 fix / 15-60 วิ เป็นตัวกันเตือนผิดจากความคลาดเคลื่อน GPS
ออกแบบมาดีแล้ว ห้ามลดในงานนี้**

## G1 · ต่ออายุการติดตามอัตโนมัติขณะยังเคลื่อนที่

### ปัญหา
live location เปิดแค่ **15 นาที ต่อหนึ่งเซสชันอาร์ม** และ `pursuitAttempted`
กันไม่ให้เริ่มใหม่ ถ้ารถถูกขับออกไปนานกว่านั้น — ซึ่งเป็นเรื่องปกติมาก —
เจ้าของจะตามต่อไม่ได้ทั้งที่รถยังเคลื่อนที่อยู่
Telegram รองรับ live location ได้ถึง 8 ชั่วโมง

### สิ่งที่ทำ
- ก่อนหมดอายุ ถ้ายังได้ fix ที่ใช้ได้และรถยังเคลื่อนที่ → ต่ออายุรอบถัดไป
- มีเพดานรวมที่ชัดเจน (เสนอ 8 ชม. เท่าที่ Telegram รองรับ) และหยุดทันทีเมื่อ Disarm
- ถ้ารถหยุดนิ่งเกินช่วงเวลาหนึ่ง → ปล่อยให้หมดอายุตามปกติ ไม่ต่อ
- แยก "หมดอายุเพราะหยุดนิ่ง" ออกจาก "หมดอายุเพราะชนเพดาน" ในข้อความถึงเจ้าของ

### ตรวจบนเครื่อง
1. Arm → พารถ/เครื่องเคลื่อนที่เกิน 100 ม. → เริ่มติดตาม
2. เคลื่อนที่ต่อเนื่องเกิน 15 นาที → **หมุดใน Telegram ต้องยังขยับอยู่ ไม่หยุดที่นาทีที่ 15**
3. จอดนิ่งทิ้งไว้ → การติดตามหยุดเองตามกำหนด พร้อมข้อความบอกว่าหยุดเพราะอะไร
4. Disarm ระหว่างติดตาม → หยุดทันที ไม่มีหมุดค้าง
5. ปิดแอปจากตัวจัดการงานระหว่างติดตาม → กลับมาแล้วสถานะต้องไม่ค้างครึ่ง ๆ กลาง ๆ

## G2 · เริ่มติดตามทันทีเมื่อมีเหตุการณ์ระดับวิกฤต

### ปัญหา
การติดตามเริ่มได้ทางเดียวคือเคลื่อนเกิน ~100 ม. ถ้ามีเหตุการณ์งัดแงะระดับวิกฤต
(สั่น + เสียง + แสง) เกิดขึ้นก่อน ระบบก็ยังต้องรอให้รถถูกเคลื่อนออกไป 100 ม. อยู่ดี
ช่วงเวลานั้นคือช่วงที่ตำแหน่งมีค่าที่สุด

### สิ่งที่ทำ
- เพิ่มทางเข้าที่สอง: เหตุการณ์ระดับ CRITICAL ในโหมดเฝ้ารถ → เริ่ม live location ทันที
  โดยไม่รอเกณฑ์ระยะทาง
- **ห้ามแตะเกณฑ์ 100 ม. เดิม** ทางเข้าเดิมต้องทำงานเหมือนเดิมทุกประการ
- ถ้าเริ่มด้วยทางเข้านี้แล้วรถไม่เคลื่อนไหวเลย ต้องหยุดเองตามกำหนดเวลา

### ตรวจบนเครื่อง
1. Arm ในโหมดเฝ้ารถ → ทำให้เกิดเหตุการณ์วิกฤตโดยไม่ย้ายรถ (เคาะ + เสียง)
   → ต้องได้ live location ทันที ทั้งที่ยังไม่ได้เคลื่อนที่
2. **เทสต์ถดถอย:** ทำให้เกิดแค่การสั่นระดับ WARNING → **ต้องไม่เริ่มติดตาม**
   (ไม่งั้นจะกลายเป็นเปิด GPS พร่ำเพรื่อ กินแบต)
3. **เทสต์ถดถอย:** ทางเข้าเดิม — เคลื่อนเกิน 100 ม. โดยไม่มีเหตุการณ์ใด ๆ
   → ต้องยังเริ่มติดตามได้เหมือนเดิม
4. ทั้งสองทางเข้าเกิดพร้อมกัน → ต้องได้ live location **ชุดเดียว** ไม่ซ้อนกันสองชุด

## สิ่งที่งานนี้ห้ามทำ

- ห้ามลดเกณฑ์ 100 ม. / 2 fix / 15-60 วิ
- ห้ามแตะ `isPrimaryRole()` หรือเรื่องบทบาทเจ้าภาพ (เป็นของ T14/T16 ในแผนหลัก)
- ห้ามเปิดการติดตามในโหมดประตูหรือโหมดไฟเลี้ยง
- ห้าม merge เข้าสาขาเดียวกับ T1-T16 ก่อนที่ทั้งสองฝั่งจะผ่านการตรวจบนเครื่องแยกกันแล้ว
