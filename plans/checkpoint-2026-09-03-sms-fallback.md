## รอบนี้ทำอะไร

รีวิวโปรเจคทั้งก้อน แล้วแก้สองข้อแรกที่รีวิวชี้ ทั้งสองข้ออยู่บนเส้นทาง SMS สำรอง
จึงรวมเป็น commit เดียว เพราะแยกแล้ว commit แรกจะทิ้ง `SmsFallbackManager` ไว้ครึ่งทาง

### ข้อ 1 — ข้อความที่อุตส่าห์สร้าง ถูกทิ้งกลางทาง

`IncidentDeliveryCoordinator` เรียก `formatter.formatSms(update)` ได้ข้อความไทยครบ
แล้วส่งเข้า `sms.send(...)` — แต่ตัวต่อสายจริงใน `ProtectionRuntimeGraph` เขียนว่า
`IncidentTransport { _ -> ... }` **ทิ้ง argument ทั้งก้อน** แล้วส่งค่าคงที่ `"SECURITY_INCIDENT"`

SMS ที่เจ้าของได้รับตอนเน็ตล่มจึงมีแค่ `ALERT:SECURITY_INCIDENT|TIME:<ms>` —
ไม่บอกว่าเกิดอะไร ไม่บอกว่าอยู่ไหน ทั้งที่ `sendEncryptedSmsAlert` มีพารามิเตอร์
`gpsLocation` ค้างอยู่ในลายเซ็น **ที่ไม่มีโค้ดบรรทัดไหนอ่านเลย** และ call site จริงก็ไม่เคยส่งมา

**แก้แล้ว:** transport รับ `message` แล้วส่งต่อจริง · `sendEncryptedSmsAlert(destination, message)`
เลิกรับ `alertType`/`gpsLocation`

### ข้อ 2 — กุญแจที่คนพิมพ์เอง ผ่าน SHA-256 รอบเดียว

`EncryptedSmsCodec.deriveKey` ใช้ `SHA-256(passphrase)` ตรง ๆ ไม่มี salt ไม่มี iteration
และหน้าตั้งค่าตรวจแค่ว่า "ไม่ว่าง" → passphrase สั้น ๆ แตกด้วย offline search จาก SMS ก้อนเดียว

**สิ่งที่เจอระหว่างแก้ และเป็นตัวตัดสินทางออก:** กุญแจนี้**ไม่เคยต้องออกจากเครื่อง**
เครื่องเซ็นเซอร์เข้ารหัส และเครื่องเดิมนั่นแหละถอดรหัสตอนเจ้าของส่ง `/decode` กลับมา
การให้คนคิดความลับที่มีแต่เครื่องใช้จึงไม่ได้อะไรเลย แลกมาด้วยจุดอ่อน

**แก้แล้ว:** สุ่ม 256 บิตในเครื่อง (`getOrCreateSmsAesKey()` เขียนด้วย `commit()` —
กุญแจที่หายเพราะ crash กลางทางแปลว่ามีข้อความบนสายที่ไม่มีอะไรเปิดได้) · ตัดช่องกรอกทิ้ง ·
`encryptSmsPayload` **ปฏิเสธ passphrase** แทนที่จะยืดเป็นกุญแจอ่อน ๆ ให้เงียบ ๆ

## การตัดสินใจที่ต้องจำ

### 🔓 พิกัดเข้า SMS แล้ว — เจ้าของเลือกเอง

เดิมมีข้อขัดแย้งอยู่ในโค้ด: หน้าตั้งค่าเขียนว่า "ไม่ส่งพิกัด GPS เพื่อความปลอดภัย"
แต่ doc comment ของ codec เขียนว่ามันเข้ารหัส "GPS coordinates + timestamp + alert type"
และพารามิเตอร์ `gpsLocation` ก็ยังค้าง — **สามอย่างนี้ขัดกันเอง**

ถามเจ้าของแล้ว **เลือกส่งพิกัด** เหตุผล: ตอนเน็ตล่มและรถหาย พิกัดคือสิ่งเดียวที่ช่วยตามคืนได้
และมันถูกเข้ารหัส AES-256-GCM อยู่แล้ว · ข้อความในหน้าตั้งค่าแก้ให้ตรงกับที่ทำจริงแล้ว

### 📍 SMS ใช้พิกัดดิบ ไม่ใช่ maps URL + ชื่อสถานที่

Telegram ได้ label ที่ผ่าน reverse geocoder + maps URL · SMS ได้แค่ `lat,lon`
เพราะการหา label ต้องยิงเน็ต **ซึ่งเป็นสิ่งที่ช่องทางนี้มีอยู่เพราะมันไม่มี**

### 🧩 พิกัดต่อในตัว formatter ไม่ใช่ที่ transport

`formatSms` มี early return สำหรับ ENTRY_DOOR และ POWER (ไปที่ `entryMessage`/`powerMessage`)
**ก่อน**ถึงบล็อก details — ถ้าเอาพิกัดไปต่อในนั้น สองโหมดที่วิกฤตที่สุดจะไม่ได้พิกัดเลย
จึงแยก `smsBody()` ออกมา แล้วต่อพิกัดหลังการแยกชนิดเหตุ

### ✂️ เพดาน 300 ไบต์ ตัดบนขอบ codepoint

ไทย 3 ไบต์/ตัว และ ciphertext โตอีก 1/3 ตอน Base64 → ข้อความไม่จำกัดกลายเป็นสิบกว่าส่วน SMS
แต่ละส่วนคือโอกาสมาถึงลำพังหนึ่งครั้ง · **วัดแล้ว: เหตุทั่วไป 2 ส่วน เพดานแย่สุด 3 ส่วน**

```
plaintext 135 ไบต์ → sealed 163 → base64 220 ตัว → +prefix = 234 ตัว → 238 septet → 2 ส่วน
เพดาน 300 ไบต์     → sealed 328 → base64 440 ตัว → +prefix = 454 ตัว → 458 septet → 3 ส่วน
```

เวลาต่อ**ท้าย** เพราะถ้ามาไม่ครบ "เกิดอะไร" มีค่ากว่า "ตอนกี่โมง"

### 🔁 สองสคีมบนสาย แยกด้วย prefix

| prefix | กุญแจ | สถานะ |
|---|---|---|
| `[ENC_ALARM_V3]` | สุ่ม 256 บิต ใช้ตรง | **อันเดียวที่สร้างใหม่ได้** |
| `[ENC_ALARM_V2]` | `SHA-256(passphrase)` | **ถอดรหัสได้อย่างเดียว** |

เก็บ V2 ไว้เพราะข้อความเก่าที่ค้างในกล่อง SMS ต้องอ่านออกอยู่ ·
`/decode` ลองกุญแจเครื่องก่อน ไม่ผ่านค่อยตกไปกุญแจเก่า · กุญแจเก่ายังอยู่ใน pref เดิม ไม่ถูกลบ

### ⚠️ "SMS พร้อมใช้งาน" เปลี่ยนความหมาย

เดิม = มีเบอร์ **และ** มีกุญแจ · ตอนนี้ = **มีเบอร์อย่างเดียว** (กุญแจสร้างเองเสมอ)
แก้ที่ `ProtectionRuntimeGraph` และ `AndroidProtectionSettingsGateway`

### 🔴 ยังพิสูจน์ไม่ได้ — ต้องให้เจ้าของทำ

**ยังไม่เคยเห็น SMS ฉบับใหม่ออกจากเครื่องจริง** ติดสี่อย่างที่ทำแทนไม่ได้:

1. การใช้งานปัจจุบันคือ **ดูแลไฟเลี้ยง** ซึ่งต้อง**ปรับเทียบไฟยืนยันก่อน arm** —
   ต้องเปิด/ปิดหลอดไฟจริงตรงหน้าเซ็นเซอร์แสง
2. เหตุ POWER ระดับวิกฤตต้องมีสองสัญญาณ: สายชาร์จหลุด **และ** ไฟยืนยันดับ
   (`adb shell dumpsys battery unplug` ทำได้ครึ่งแรก ครึ่งหลังต้องบังแสงจริง)
3. เบอร์ปลายทางที่เก็บไว้เป็นเบอร์จริงของเจ้าของ **อ่านไม่ได้** (อยู่ใน EncryptedSharedPreferences)
   และ**ห้ามเขียนทับ** เพราะจะทำให้ SMS ฉุกเฉินยิงผิดเบอร์
4. `/decode` ต้องส่งจากบัญชี Telegram ของเจ้าของ

**วิธีพิสูจน์ที่ง่ายที่สุด** (เลี่ยงการปรับเทียบแสงทั้งหมด):

```
1. เปลี่ยนการใช้งาน → ปกป้องรถ (VEHICLE)   ← สั่นถึงระดับวิกฤตได้ ไม่ต้องปรับเทียบแสง
2. เปิดระบบป้องกัน
3. adb shell svc data disable  (หรือเปิดโหมดเครื่องบิน) ← ทำให้ Telegram ส่งไม่สำเร็จ
4. เขย่าเครื่องแรง ๆ จนเปิดเหตุการณ์
5. ดูมือถือหลัก: ต้องได้ SMS ที่ขึ้นต้น [ENC_ALARM_V3] ← V3 ไม่ใช่ V2 คือหลักฐานว่ากุญแจใหม่ทำงาน
   นับจำนวนส่วนที่ได้ ควรเป็น 2 ส่วน ไม่ควรเกิน 3
6. adb shell svc data enable  แล้วส่ง /decode <ทั้งข้อความ> ให้บอท
   ต้องอ่านได้เป็นภาษาไทย + บรรทัด "📍 พิกัด: ..." + บรรทัด TIME
7. ปิดระบบป้องกัน แล้วเปลี่ยนการใช้งานกลับเป็น ดูแลไฟเลี้ยง
```

⚠️ ขั้นที่ 4 จะยิง **SMS จริง เสียเงินจริง** เข้าเบอร์ที่ตั้งไว้ และขั้นที่ 2 อาจส่งข้อความเข้า Telegram ของเจ้าของ
