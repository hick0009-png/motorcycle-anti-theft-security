### บั๊กที่เจอระหว่างทาง

เครื่องเปิดเซ็นเซอร์หมุนได้พร้อมกันหลายตัว (INE-LX2 มีครบทั้ง 3) และ quaternion ของแต่ละตัว
**ไม่ใช่ปริมาณเดียวกัน** — เอาค่าของตัวหนึ่งไปเทียบกับจุดตั้งต้นของอีกตัวจะได้ "การหมุน" ที่ไม่เคยเกิด
คือรายงานว่าเครื่องแกว่งในคืนที่มันนอนนิ่ง แก้เป็น: **มีตัวเดียวถือคอลัมน์ไว้** เรียงตาม
`EntryOrientationSourcePolicy.PREFERENCE` (ลำดับเดียวกับที่โหมดประตูใช้) ตัวที่ดีกว่ามาทีหลัง
ยึดคอลัมน์ไปแล้ว**เริ่มจุดตั้งต้นของตัวเอง** ไม่รับมรดกของตัวอื่น

ไจโรปล่อยว่างไว้ เพราะมันรายงานอัตราไม่ใช่มุม — ตัวเลขผิดหน่วยใต้หัวคอลัมน์ที่ถูก
แย่กว่าช่องว่าง เพราะช่องว่างเชื่อผิดไม่ได้

### 1. ให้เครื่องเรียนรู้ดริฟท์ต่อเนื่องระหว่างใช้จริง  ← แนะนำทำก่อน

ตอนนี้เครื่องรู้จักตัวเองเฉพาะตอนกดปุ่มวัดเอง ซึ่งผู้ใช้ส่วนใหญ่จะไม่กด
ทุกครั้งที่อาร์มโหมดประตูแล้วออกจากบ้าน เครื่องกำลังทำการทดลองเดียวกันอยู่แล้ว แค่ไม่มีใครจด

- ของที่มีให้ใช้ต่อ: `EntryDriftSampler`, `lastMovementElapsedMs` ใน `IncidentEngine`
  (ใช้แยกว่าช่วงไหน "เงียบจริง"), `EntryDriftMeasurementStore` ที่เก็บอันวัดนานกว่าอยู่แล้ว
- ⚠️ กับดัก: ถ้านับช่วงที่ประตูเปิดจริงหรือมีคนขยับเครื่องเข้าไปด้วย เครื่องจะ "เรียนรู้" ว่า
  ตัวเองดริฟท์เร็วมาก แล้ว**ปฏิเสธโหมดประตูของตัวเองทิ้ง** ต้องกันด้วยเงื่อนไขเงียบสนิทเท่านั้น

### 2. ระบบฆ่าแอปของแต่ละยี่ห้อ

มี `AutoStartPermissionHelper` (รู้จัก Huawei/Honor, Xiaomi/Redmi/Poco, Oppo/Realme, Vivo/iQOO)
กับปุ่มขอยกเว้นประหยัดแบตอยู่แล้ว **ที่ขาดคือ:**

1. ไม่มีใครจดว่าแอปเคยถูกฆ่าไปหรือเปล่า — มี heartbeat แต่ไม่มีบันทึกว่า
   "เมื่อคืนตี 3 บริการหายไป 40 นาทีระหว่างที่อาร์มอยู่" ซึ่งคือช่วงที่ไม่มีการปกป้องจริง
2. กดเปิดหน้า auto-start ได้ แต่อ่านไม่ได้ว่าผู้ใช้กดอนุญาตจริงไหม (Android ไม่ให้อ่าน)

## ข้อพิสูจน์ที่ต้องให้เจ้าของทำเอง (ไม่ใช่งานเขียนโค้ด)

1. 🔴 **เปิดประตูจริงแล้วต้องยังเตือนได้** — Arm โหมดประตู → เปิดประตู → ต้องได้ "🚪 ตรวจพบประตูเปิด"
   ถ้าเงียบ = การยับยั้งด้วยการสั่น (`6299080`) แรงเกินไป ต้องกลับมาแก้ทันที
   (จุดที่น่าจะพลาด: หน้าต่าง 10 วินาที หรือ `movementCorroborationArmed()` ตอบผิด)
2. **กล่องดำ: คอลัมน์เซ็นเซอร์ตอนอาร์มจริง** — arm → รอ 2 นาที → เขย่า → อ่านไฟล์
   `samples` ต้องมีเลข · `accMaxG` ต้องกระโดดในนาทีที่เขย่า (ดูหัวข้อ B2)
3. **กล่องดำ: แถว `stop` ตอนปิดบริการจากในแอป** — พิสูจน์บนเครื่องยังไม่ได้ (`am stopservice` ไม่ผ่าน)
   กดหยุดบริการในแอป → แถวสุดท้ายต้องมี `stop` ถ้าไม่มี การปิดปกติจะอ่านเหมือนถูกฆ่าทุกครั้ง
   (มีเทสต์ host คุมไว้แล้ว ที่ขาดคือการยืนยันว่า `onDestroy` ถูกเรียกจริงบนเส้นทางนั้น)
4. **T9 ดูด้วยตา** — ตั้งบทบาทเซ็นเซอร์ในโหมดหนึ่ง → สลับโหมด → ค่าต้องไม่ตามไป → สลับกลับต้องยังอยู่
5. ข้อพิสูจน์ T7 สองข้อที่ค้างจากเซสชันก่อน (ปิดบทบาทแกนหมุน / ลดบทบาทแสงในโหมดไฟเลี้ยง)
6. เลือกการใช้งานใหม่ในแอป — เครื่อง disarm อยู่หลังทดสอบ force-stop

## กับดักที่ต้องจำ (อ่านก่อนแตะโค้ดที่เกี่ยวข้อง)

| แตะอะไร | ต้องระวัง |
|---|---|
| การยับยั้งด้วยการสั่น | **เครื่องที่ไม่มีเซ็นเซอร์สั่น หรือโหมดที่ไม่ได้เปิดใช้ ห้ามถูกยับยั้ง** ไม่งั้นโหมดประตูเงียบทั้งเครื่องโดยไม่มี error |
| ผลวัดดริฟท์ | **เครื่องที่ยังไม่เคยวัด = ใช้ได้ตามปกติ** ถ้าทำให้ "ไม่เคยวัด = น่าสงสัย" โหมดประตูจะหายจากทุกเครื่องในสนาม |
| หน้าตั้งค่าเซ็นเซอร์ | เก็บเป็น**ส่วนต่างจากค่าแนะนำ** ไม่ใช่ทั้งชุด · เซ็นเซอร์ที่โหมดล็อกปิดไว้ห้ามบันทึกเป็นความตั้งใจของเจ้าของ |
| สีในธีม | `ProtectionPaletteContrastTest` คำนวณคอนทราสต์จริง แก้สีจนตกเกณฑ์ AA = เทสต์แดง |
| `isPrimaryRole()` / ตารางเจ้าภาพ | `LOCATION` ต้องเป็นเจ้าภาพของโหมดเฝ้ารถเสมอ ไม่งั้นการเตือน "รถถูกเคลื่อนย้าย" เงียบทั้งหมด |
| จุด tap ของกล่องดำ | **ห้าม `registerListener` ตัวใหม่เด็ดขาด** — Android ให้ทุก client ได้ rate ที่เร็วที่สุดที่มีใครขอ ยามที่ตั้ง 5 Hz จะวิ่ง 50 Hz กินไฟ 10 เท่าโดยไม่มี error · และห้าม alloc/ล็อก/แตะดิสก์บนเธรดนั้น |
| กล่องดำ | **แถวที่เขียนบ่อยกว่านาทีละครั้งจะฆ่ากล่องดำเอง** — ชนเพดานไฟล์แล้วหยุดบันทึกทั้งคืน · ห้ามเขียนจากเธรดเซ็นเซอร์ |
| รันเทสต์บนเครื่อง | ถ้าแดงทั้งชุดด้วย `No compose hierarchies found` = จอหลับ ไม่ใช่โค้ดพัง → `adb shell svc power stayon usb` แล้วปลุก · และ gradle **ถอนแอปออกหลังรันเสร็จ** ต้อง `installDebug` กลับ |
